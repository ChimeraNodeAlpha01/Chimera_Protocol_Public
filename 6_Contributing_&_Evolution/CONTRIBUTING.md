# Contributing to the Chimera Protocol | 贡献奇美拉协议指南

Thank you for your interest in contributing to this thought experiment. We view all contributions—questions, critiques, expansions—as a form of collaborative "pressure testing" essential for refining the protocol drafts.

感谢您有兴趣为这项思想实验做出贡献。我们将所有形式的贡献——提问、批判、拓展——视为一种协作式的“压力测试”，这对于完善协议草案至关重要。

## 💭 Contribution Philosophy | 贡献理念

Our primary goal is **rigorous scrutiny and collaborative ideation**, not code implementation (at this stage). We value:
我们的首要目标是**严格的审视与协作构思**，而非代码实现（在现阶段）。我们重视：

*   **Conceptual Clarity & Logical Rigor** | **概念清晰与逻辑严谨**
*   **Identification of Hidden Assumptions & Blind Spots** | **识别隐藏假设与盲点**
*   **Cross-disciplinary Bridging** (e.g., translating a cryptographic concern into a societal risk) | **跨学科桥接**（例如，将密码学问题转化为社会风险）
*   **"Stress Testing" Under Extreme or Edge Cases** | **在极端或边缘案例下的“压力测试”**

We are particularly seeking insights on:
我们尤其需要以下领域的见解：

1.  **Technical Feasibility & Attack Vectors** | **技术可行性与攻击向量**

    *   “宏观上帝视角”的合法性及其潜在偏见。

    *   Unintended consequences or perverse incentives within the frameworks.
    *   框架内可能产生的意外后果或不良激励。

    *   三方制衡的失效模式。

    *   Translating protocol concepts into relatable analogies or stories.
    *   将协议概念转化为易于理解的类比或故事。

## 📖 How to Contribute | 如何贡献

### 1. Engage in Discussion | 参与讨论
*   **Primary Channel**: [GitHub Issues](https://github.com/ChimeraNodeAlpha01/Chimera_Protocol_Public/issues).
*   **主要渠道**：[GitHub Issues](https://github.com/ChimeraNodeAlpha01/Chimera_Protocol_Public/issues)。
*   Please use clear, descriptive titles for new issues (e.g., "[DSEAP] Question on entropy source stability", "[Education] Potential loophole in 15% zone evaluation").
*   请为新的Issue使用清晰、描述性的标题（例如：“[DSEAP] 关于熵源稳定性的问题”、“[教育] 15%区域评估中的潜在漏洞”）。
*   Reference specific documents, sections, and ideas when possible.
*   尽可能引用具体的文档、章节和观点。

### 2. Propose Changes or Additions | 提议修改或增补
*   For significant textual amendments or new protocol ideas, **please first open an Issue for discussion** before submitting a Pull Request (PR).
*   对于重大的文本修改或新的协议构想，**请在提交拉取请求（PR）之前，先开设一个Issue进行讨论**。
*   This ensures the community (however small) can align on the direction.
*   这能确保（无论多小的）社区能在方向上达成一致。

### 3. Submit a Pull Request (PR) | 提交拉取请求
*   Once a proposal is discussed and has preliminary consensus, you may submit a PR.
*   当一个提议经过讨论并形成初步共识后，您可以提交PR。
*   **Branch Naming**: Please create a branch with a descriptive name (e.g., `fix-typo-worldview`, `propose-translation-glossary`).
*   **分支命名**：请创建一个描述性的分支（例如：`fix-typo-worldview`, `propose-translation-glossary`）。
*   **PR Description**: Clearly link to the related Issue and summarize the changes. Explain the rationale.
*   **PR描述**：清晰关联到相关的Issue，并总结更改内容。解释其理由。
*   **Scope**: Keep PRs focused on a single topic or fix.
*   **范围**：保持PR专注于单一主题或修复。
*   **Language**: For text changes, maintain bilingual updates (ZH/EN) if applicable. If you can only provide one language, state so, and we will seek translation help.
*   **语言**：对于文本修改，如适用，请保持中英双语更新。如果您只能提供一种语言，请说明，我们将寻求翻译帮助。

### 4. Provide External References | 提供外部参考
*   If you know of relevant research papers, existing projects, or philosophical works, please share them in an Issue with a brief explanation of relevance.
*   如果您了解相关的研究论文、现有项目或哲学著作，请在Issue中分享，并附上简要的相关性说明。
